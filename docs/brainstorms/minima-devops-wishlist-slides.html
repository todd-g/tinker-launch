00
How to read this

A wishlist,
not a blueprint.

We describe the developer experience we want and the outcomes we're asking for. Every choice — tooling, cloud services, the database technique, IaC, CI, build-vs-buy — is yours.

Each ask is an outcome plus acceptance criteria. No mandated tech.

01
The north star

A developer opens a PR and automatically gets a complete, isolated, production-like environment — with its own database — that runs every check and QA pass, surfaces the results in one place, and tears itself down on merge.

02
From → To

Five things have to change.

Deploys run from a laptop — not standardized or recorded
→
Standardized cloud deploys, status-tracked
One shared staging — one feature at a time, work collides
→
One isolated environment per feature — parallel by default
New DB → manually repoint a staging env var
→
Auto-wired databases — each env knows its own DB
Secrets in a plaintext txt file in S3
→
Structured, per-env, self-service, audited config
Can't see what's deployed where, on which DB
→
One control plane for every env, deploy & job

A day in the life

Ship a feature.

01

Branch & code. Off main, start working.

02

Push / open a PR. That's enough — no script, no setup.

03

A preview env spins up — with its own fresh database, wired automatically.

04

Migrations apply to that DB as part of the flow.

05

Gates run, then report back. Objective checks first; then advisory agentic QA.

06

Watch it in one control plane. Env, DB, status, results — one screen.

07

Merge. Prod auto-deploys; the env, its DB & config tear themselves down.

06
Asks 01 · 02 · 04 · 05

Every branch is its own world.

ENV + DB

Every branch gets a full, production-like environment with its own database — provisioned automatically, usable in minutes.

AUTO-WIRED

The env knows its own database. No one ever hand-edits a connection string.

MIGRATIONS

A schema change rides the branch and applies to that env's DB automatically — same path to prod.

TEARDOWN

On merge, the env + its database + its config reclaim themselves. Nothing lingers, no graveyard.

07
Ask 03

Replace the S3 text file.

STRUCTURED

Config & secrets stored per environment — secure, access-controlled, audited. Not shared plaintext.

SELF-SERVICE

A developer adds or updates a var for their feature themselves — scoped to the right env, no ticket.

AUTO-INJECT

The database connection is supplied to the app automatically — never hand-pasted.

LOOK-UP

…and easy to securely look up when you need to point a local psql at a feature DB. Audited read.

08
Asks 06 · 07 · 08

Two tiers, in order.

Tier 1 · Blocking

Objective checks

  • Automated bug & security review
  • Tests, lint, types
  • Bonus: one-click developer-reviewed fixes
Gates the merge · cheap · runs first
→
Tier 2 · Advisory

Agentic layer

  • Does the e2e suite actually cover this feature?
  • Human-language browser QA on the live env
  • Explains itself · never traps you on a flaky verdict
Only runs if Tier 1 passes
09
Ask 08 · The bet

QA written like a human, run by a machine.

"Log in, create a project, confirm it appears" — not click .fragile-dom-class. An agent drives a real browser through plain-intent scripts against each PR's environment.

Engine: our own propagator orchestrator — we already have it
10
Asks 09 · 10

Off laptops. Onto one screen.

CLOUD DEPLOYS

Deploys run in the cloud through a standard pipeline — every one recorded: what, where, when, who, which commit. Queryable status.

CONTROL PLANE

One pane of glass for every environment — URL, deploy status, which DB it points at, check & QA results, age, cost.

ACTIONS

And buttons to act — redeploy, destroy, run QA, promote. Reflects reality with no manual updating.

11
Across everything

Non-
negotiables.

These hold for every ask on the list.

OBSERVABLE
If it runs, it's visible. Status & logs for every env, deploy, migration & job.
SAFE
Easy, obvious rollback. Prod is always releasable.
ACCESS
Who deploys, destroys, reads secrets — enforced.
COST
Idle envs don't quietly pile up. Auto-reclaimed; cost attributable per env.
AUDIT
Who changed what, when.
